# Медикаменте — Стратегия защиты данных


## 1. Классификация данных

Данные «Медикаменте» разделены на шесть категорий по типу, уровню чувствительности и профилю риска. Для каждой категории определены необходимость защиты и применяемые инструменты — как при хранении (at-rest), так и при передаче (in-transit).


### 1.1 Персональные данные (ПДн) пациентов

| Тип данных | Чувствительность | В чём необходимость защиты | Инструменты защиты (при хранении) | Инструменты защиты (при передаче) | Контроль и мониторинг |
|---|---|---|---|---|---|
| ФИО, дата рождения | Высокий | 152-ФЗ ст. 3, 10 — идентификатор субъекта ПДн; раскрытие влечёт дисквалификацию и штраф | AES-256 (pgcrypto/Vault Transit); UUID-псевдонимизация вместо ФИО в именах сущностей | TLS 1.3; передача только через API Gateway; JWT без ФИО в payload | Audit Log (ELK): каждый SELECT фиксируется; алерт при массовой выгрузке |
| Телефон, email | Высокий | 152-ФЗ ст. 3 — контактные данные; риск спама, социальной инженерии, мошенничества | Шифрование колонки; маскирование при отображении (+7 *** *** 78-90) | TLS 1.3; в уведомлениях — только `patient_uuid`, без контактов в payload | Audit Log; DLP-политика на запрет копирования на USB |
| Адрес прописки, место работы | Высокий | 152-ФЗ ст. 3 — ПДн; раскрытие создаёт риски безопасности субъекта | Шифрование at-rest; сбор только при наличии явного согласия (Consent Service) | TLS 1.3; HTTPS-only; не передаётся в аналитический слой | ABAC: доступ только администратору ресепшена; логирование обращений |

### 1.2 Медицинские данные

| Тип данных | Чувствительность | В чём необходимость защиты | Инструменты защиты (при хранении) | Инструменты защиты (при передаче) | Контроль и мониторинг |
|---|---|---|---|---|---|
| Диагнозы, заключения врачей | Критический | 152-ФЗ ст. 10 — специальная категория ПДн; требует явного согласия и усиленной защиты | AES-256 на уровне поля (Vault Transit); ABAC — врач видит только своих пациентов; версионирование записей | mTLS между сервисами; ответ API не содержит ФИО, только `patient_uuid` | Audit Log с `data_class=medical:critical`; алерт при доступе вне рабочих часов |
| Результаты лабораторных анализов | Критический | 152-ФЗ ст. 10 — специальная категория; раскрытие нарушает врачебную тайну | Шифрование at-rest; Row-Level Security в PostgreSQL (пациент видит только свои строки) | mTLS API с лабораторией (mutual TLS, замена email); API-контракт скрывает лишние поля | Row-Level Security + Audit Log; алерт при запросе данных не своего пациента |
| История посещений, медкарты | Высокий | 152-ФЗ ст. 10; косвенное раскрытие диагноза; хранить 10 лет (Приказ МЗ РФ) | Шифрование at-rest; UUID вместо ФИО в именах файлов; версионирование | TLS 1.3; HTTPS; данные не передаются в открытых email-уведомлениях | Audit Log; retention policy — автоудаление по тегу `medical:10y` |
| Хронические заболевания (анкеты) | Критический | 152-ФЗ ст. 10 — спецкатегория; бумажные анкеты без регламента хранения — критический риск | Оцифровка + шифрование; физическое уничтожение бумаг (шредер); регламент хранения | Данные вводятся только через защищённый портал (HTTPS); не передаются по email | Регламент уничтожения; инвентаризация бумажных носителей |

### 1.3 Финансовые данные

| Тип данных | Чувствительность | В чём необходимость защиты | Инструменты защиты (при хранении) | Инструменты защиты (при передаче) | Контроль и мониторинг |
|---|---|---|---|---|---|
| Платёжные данные, PAN карты | Высокий | PCI DSS, ФЗ-161; хранение PAN локально — прямое нарушение; риск финансового мошенничества | Токенизация — PAN не хранится локально; платёжный шлюз PCI DSS-compliant | TLS 1.3; переадресация во внешний провайдер; локально хранится только токен | Audit Log транзакций; алерт на аномальные суммы; PCI DSS-аудит |
| Данные о платежах за услуги | Высокий | Связка «платёж — услуга» косвенно раскрывает диагноз; ФЗ-161; хранить 7 лет (НК РФ) | 1С в клиент-серверном режиме (PostgreSQL); RBAC внутри 1С; шифрование at-rest | TLS вместо незашифрованного OLE/TCP; шифрованный Event Bus (Kafka TLS) | Audit Log; контроль разграничения ролей в 1С; retention policy `financial:7y` |
| Зарплаты и кадровые данные сотрудников | Высокий | 152-ФЗ — ПДн сотрудников; доступ должен быть ограничен HR/бухгалтерией | Отдельная схема БД; шифрование at-rest; RBAC — доступ только роли `BOOKKEEPER`/`HR` | TLS 1.3; передача только через внутренний API с JWT-авторизацией | Audit Log; ABAC: изоляция от медицинских и складских данных |

### 1.4 Операционные данные

| Тип данных | Чувствительность | В чём необходимость защиты | Инструменты защиты (при хранении) | Инструменты защиты (при передаче) | Контроль и мониторинг |
|---|---|---|---|---|---|
| Журналы записи к специалистам | Средний | Содержат имена и расписание — ПДн; без версионирования невозможен аудит изменений | Шифрование; UUID вместо ФИО; версионирование записей в БД | TLS 1.3; RBAC — только роль `ADMIN_RECEPTION` имеет право записи | Audit Log; версионирование; алерт при массовом редактировании |
| Данные ТМЦ и закупок (склад) | Низкий | Не содержат ПДн пациентов; риск раскрытия коммерческой информации о закупках | 1С:Торговля в клиент-серверном режиме; RBAC — доступ только роли `WAREHOUSE` | TLS/Kafka TLS для синхронизации с бухгалтерией; накладные верифицируются | Audit Log операций с ТМЦ; верификация входящих накладных от поставщиков |

### 1.5 Инфраструктурные и аналитические данные

| Тип данных | Чувствительность | В чём необходимость защиты | Инструменты защиты (при хранении) | Инструменты защиты (при передаче) | Контроль и мониторинг |
|---|---|---|---|---|---|
| Ключи шифрования, секреты, пароли | Критический | Компрометация ключей = компрометация всех зашифрованных данных | HashiCorp Vault: централизованное хранение; dynamic secrets; ротация по расписанию | Vault API over TLS; ключи никогда не передаются в открытом виде | Vault Audit Log; алерт при нестандартном обращении к ключам |
| Обезличенные данные (Data Lake) | Низкий | Обезличены, но требуют контроля: повторная идентификация возможна при слабой анонимизации | Хранение в изолированном Anon Zone; k-anonymity; UUID вместо ФИО | Доступ только через внутренний BI-инструмент (Apache Superset); нет прямого доступа к Operational DB | Data Catalog (OpenMetadata): тегирование; Data Lineage; контроль процедур обезличивания |

## 2. Автоматизированный контроль

Для обеспечения автоматизированного контроля каждый атрибут данных помечается тегом по трёхосевой таксономии: `{data_class}:{sensitivity}:{retention}`. Теги используются системами аудита, ETL-пайплайном и механизмом автоматического удаления данных по истечении срока хранения.

| Тег | Расшифровка | Данные | Срок хранения |
|---|---|---|---|
| `medical:critical:10y` | Медицинские данные — критическая категория | Медкарты, диагнозы, результаты анализов | 10 лет (Приказ МЗ РФ) |
| `pii:high:5y` | ПДн — высокая чувствительность | ФИО, дата рождения, телефон, email | 5 лет после последнего визита |
| `financial:high:7y` | Финансовые данные — высокая чувствительность | Платёжные данные, зарплаты, налоги | 7 лет (НК РФ) |
| `operational:medium:1y` | Операционные данные — средняя чувствительность | Журналы записей, логи | 1 год |
| `internal:low:1y` | Внутренние данные — низкая чувствительность | Данные ТМЦ, закупки | 1 год |

## 3. Реестр программных и аппаратных средств защиты


| Категория | Инструмент | Назначение | Уровень применения | Приоритет |
|---|---|---|---|---|
| Шифрование | **HashiCorp Vault** | Управление ключами, Dynamic secrets, Transit Encryption для PII-полей | At-rest / Инфраструктура | Высокий |
| Шифрование | **PostgreSQL pgcrypto + RLS** | Шифрование колонок с ПДн; Row-Level Security — изоляция данных на уровне СУБД | At-rest / СУБД | Высокий |
| Шифрование | **MinIO (S3) server-side encryption** | Шифрование at-rest для Data Lake (Raw Zone) | At-rest / Хранилище | Средний |
| Шифрование | **Kafka TLS + Schema Registry** | Шифрование сообщений в Event Bus; тегирование топиков по чувствительности | In-transit / Шина | Высокий |
| Управление доступом | **Keycloak (IAM/SSO)** | OAuth2/OIDC аутентификация, MFA, управление ролями RBAC (DOCTOR, ADMIN, CASHIER, WAREHOUSE, BOOKKEEPER) | Identity / Edge | Критический |
| Управление доступом | **ABAC-политики в сервисах** | Врач видит только своих пациентов; пациент — только свои данные (Row-Level Security) | Приложение / СУБД | Критический |
| Управление доступом | **API Gateway (Kong/NGINX)** | Единая точка входа: TLS 1.3, rate-limiting, IP-фильтрация, JWT-валидация | Edge / Network | Критический |
| Управление согласиями | **Consent Service (кастомный)** | Хранение согласий 152-ФЗ, workflow удаления данных (право на забвение, ст. 21) | Приложение | Высокий |
| Передача данных | **TLS 1.3 (все каналы)** | Шифрование всех HTTP/API-соединений; замена незашифрованного OLE/TCP | In-transit | Критический |
| Передача данных | **mTLS (mutual TLS)** | Взаимная аутентификация при интеграции с внешней лабораторией | In-transit / Интеграция | Высокий |
| Передача данных | **Платёжный шлюз PCI DSS** | Токенизация PAN; PAN не хранится и не передаётся через внутренние системы | In-transit / Платежи | Критический |
| Аудит и мониторинг | **ELK Stack** (Elasticsearch + Logstash + Kibana) | Централизованный Audit Log: `user_id`, `action`, `data_class`, `resource_id`, `timestamp` | Мониторинг | Критический |
| Аудит и мониторинг | **Victoria Metrics + Alertmanager** | Метрики производительности + алертинг при аномалиях доступа | Мониторинг | Высокий |
| Аудит и мониторинг | **Windows Server File Auditing (AD)** | Немедленная мера: аудит доступа к файлам на файловом сервере (Quick Win) | Мониторинг / AS-IS | Срочный |
| Каталог данных | **Apache Atlas / OpenMetadata** | Data Catalog: тегирование полей `{data_class}:{sensitivity}:{retention}`, Data Lineage граф | Governance | Средний |
| Управление данными | **Data Governance Portal** (Atlas UI) | DPO-портал: статус согласий, retention policies, отчёты 152-ФЗ, статус запросов на удаление | Governance | Средний |
| Обезличивание | **Apache Spark / dbt** (ETL Pipeline) | Автоматическое обезличивание перед загрузкой в Data Lake; k-anonymity; псевдонимизация | Analytics | Средний |
| ML/BI | **Apache Superset** (BI) | Дашборды только на основе Anon Zone; нет прямого доступа к Operational DB | Analytics | Низкий |
| ML/BI | **Jupyter + MLflow + PyDP** | Обучение ML-моделей на обезличенных данных; дифференциальная приватность | Analytics | Низкий |
| Физическая защита | **DLP-политика** (AD Group Policy) | Запрет копирования файлов на USB-носители; контроль съёмных устройств | Endpoint | Срочный |
| Физическая защита | **Шредер + регламент уничтожения** | Уничтожение бумажных анкет с ПДн после оцифровки | Физическая | Срочный |
