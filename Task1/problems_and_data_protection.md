## 2. Список проблемных зон

### КРИТИЧЕСКИЕ проблемы

#### P-01: Отсутствие шифрования данных в хранилищах
- **Что происходит:** Все данные пациентов — медицинские карты, списки, журналы — хранятся в незашифрованных файлах (Excel, PDF, JPG) на общем файловом сервере.
- **Риск:** Любой пользователь домена или злоумышленник, получивший доступ к диску, получает полный доступ ко всем медицинским данным.
- **Нарушение:** 152-ФЗ, ст. 19 — обязательные технические меры защиты ПДн.

#### P-02: Отсутствие разграничения доступа к данным (нет RBAC/ABAC)
- **Что происходит:** Единственный механизм контроля доступа — доменная аутентификация (Active Directory). После входа в домен пользователь имеет доступ ко всему файловому серверу.
- **Риск:** Врач видит данные всех пациентов (не только своих). Кассир видит медицинские карты. Кладовщик видит финансовые данные.
- **Нарушение:** Принцип минимальных привилегий (Least Privilege), 152-ФЗ.

#### P-03: Имена папок пациентов содержат ФИО (PII в метаданных ФС)
- **Что происходит:** Структура папок вида `Pacient1-FIO-BD` делает ФИО пациента видимым в файловой системе без открытия самих файлов.
- **Риск:** Утечка PII через логи файловой системы, резервные копии, индексирование.
- **Нарушение:** Data Minimization, 152-ФЗ.

#### P-04: Передача данных между ККМ и 1С без шифрования (TCP/IP-OLE)
- **Что происходит:** Финансовые транзакции передаются по локальной сети через OLE без TLS/шифрования.
- **Риск:** Перехват данных о транзакциях при компрометации сети (MITM-атака).
- **Нарушение:** PCI DSS, ФЗ-161.

#### P-05: Отсутствие аудита доступа к данным (нет Data Lineage)
- **Что происходит:** Нет логирования того, кто открывал, изменял или копировал файлы с данными пациентов.
- **Риск:** Невозможно обнаружить утечку данных. Нельзя провести расследование инцидента.
- **Нарушение:** 152-ФЗ ст. 19, требования регулятора по аудиту ПДн.

### ВЫСОКИЕ проблемы

#### P-06: Двойной ручной учёт (Excel + 1С) — риск несогласованности данных
- **Что происходит:** Кассиры вносят данные о платежах вручную в Excel И в 1С одновременно.
- **Риск:** Расхождения в данных, ошибки, возможность мошенничества через манипуляцию одной из копий.

#### P-07: Нет API-интеграции с внешней лабораторией
- **Что происходит:** Результаты анализов передаются вручную через email или файлы.
- **Риск:** Незашифрованная передача медицинских данных по email. Нет верификации целостности данных. Один реестр содержит данные всех пациентов.

#### P-08: 1С в файловом режиме — нет защиты на уровне СУБД
- **Что происходит:** Обе системы 1С работают в файловом режиме (не клиент-серверном), т.е. файлы базы данных доступны напрямую.
- **Риск:** Кража базы данных путём копирования файла без каких-либо ограничений.

#### P-09: Отсутствие механизма удаления данных (право на забвение)
- **Что происходит:** Нет регламента и технического механизма удаления данных пациента по его запросу.
- **Нарушение:** 152-ФЗ ст. 21 — пациент вправе потребовать удаления своих ПДн.

#### P-10: Exchange Mail Server — электронная почта не шифруется
- **Что происходит:** Уведомления врачам о записях пациентов отправляются через внутреннюю почту без end-to-end шифрования.
- **Риск:** Утечка данных о пациенте (ФИО, время приёма, специалист) через почтовый сервер.

---

### СРЕДНИЕ проблемы

#### P-11: Отсутствие классификации данных (Data Classification)
- Данные разной степени конфиденциальности хранятся вместе без маркировки.

#### P-12: Нет версионирования файлов
- Изменения в журналах и медкартах не отслеживаются — невозможно откатить изменения.

#### P-13: Бумажные формы с ПДн пациентов
- Расширенные анкеты на бумаге не имеют регламента безопасного хранения и уничтожения.

#### P-14: Отсутствие резервного копирования с контролем доступа
- Нет информации о регламенте резервного копирования и доступа к резервным копиям.

#### P-15: Один физический сервер — единая точка отказа
- Все системы на одном сервере в том же здании — риск катастрофической потери данных.
